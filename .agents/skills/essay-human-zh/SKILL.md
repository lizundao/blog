# 中文随笔（essay-human-zh）

> 目标：**优雅、真切**——读起来像作者本人讲一件刚发生的事，不是 AI 输出范文，也不是为检测器优化的「糙稿」。
> 参考 avoid-ai-writing、humanizer-zh 等 skill，针对守遵寻道中文随笔裁剪。

---

## 何时启用

- 新建或润色 `src/content/essay/*.md`
- 用户提到：去 AI 味、润色、随笔、太像机器写的
- 初稿由 AI 生成，需要改到像作者本人

**不要**用于：API 文档、README、造物产品介绍（结构可稍整）。

---

## 守遵寻道声线

先读样本（若仓库里有）：

- `src/content/essay/de-ai-flavor.md`
- `src/content/essay/microsoft-license-call.md`
- `src/content/essay/crm-erp-api-integration.md`

声线要点：

1. **先事后人** — 从具体场景切入
2. **真诚、克制** — 像熟人聊天，不像公关稿或得到体
3. **句子长短错落** — 不必刻意口癖，但别句句对称
4. **有锚点** — 系统名、日期、原话、小转折
5. **道理藏在事里** — 少喊口号；结尾可收束，不必金句
6. **优雅优先** — 不为一过检测器而故意写糙、写乱

---

## 工作流

1. 读原文 + frontmatter；不改 `pubDate`、`cover` 路径
2. 重写正文；保留事实，不编造未提及的经历
3. 过自检清单
4. 只输出完整 Markdown，不解释

---

## 应删或削减的模式

| 模式 | 处理 |
|------|------|
| 「写在后面」「综上所述」 | 自然收束，或换不模板的小标题 |
| 编号清单（1.2.3.） | 改连贯段落，除非真是步骤 |
| 「愿我们……」 | 禁止 |
| 连续排比、对称「不是…而是…」 | 最多 0～1 次 |
| 加粗金句堆砌 | 全文 0～1 处，最好不用 |
| 第二人称教程腔（「你若…不妨…」） | 改「我」或省略 |
| 赋能、闭环、抓手等 AI 高频词 | 换 plain 中文 |

---

## 应保留的优雅

- 适度小标题（2～4 个），不必全删
- 具体名词：销售易、金蝶、Postman、ResAPI
- 一段一事，段落长度有变化
- 结尾一句淡的感想，不必升华

---

## 自检清单

- [ ] 至少 3 个具体锚点？
- [ ] 有没有编号列表、排比堆砌？
- [ ] 读出声来像不像作者在讲，而不是在上课？
- [ ] 事实有没有编造？
- [ ] **是否优雅**——不糙、不乱、不模板？

---

## 与其他工具

- `npm run essay:polish` — 润色后仍须过本 skill
- AI 检测器（朱雀等）— **仅作参考，不追求过关**；读者觉得真好，比分数重要

详细模式见 `references/zh-ai-patterns.md`。
